# ECO 成本计算器（简体中文）

这是 [Gonozal/eco-cost-calculator](https://github.com/Gonozal/eco-cost-calculator) 的简体中文 fork。项目已将原版 ECO 数据与计算模型更新到 **ECO 14.0.3**，并完成界面、配方、物品、职业、制作站、网页元数据和使用说明的中文本地化。

在线使用：[https://lonelygeo.github.io/eco-cost-calculator/](https://lonelygeo.github.io/eco-cost-calculator/)

## 使用方法

计算器以配方为入口。在右侧“产品”区域选择要计算的制作配方后，主要产物会自动加入产品列表，所需材料会加入“原料”，炉渣、尾矿、桶等产出则会加入“副产品”。对应的职业与制作站也会自动出现。

配方搜索默认只匹配产品的中文名和英文名，并按完整匹配、开头匹配、包含匹配排序。需要按制作站或内部配方 ID 查找时，可分别输入 `制作站:机械师工作台` 或 `id:BoilerRecipe`；搜索结果会同时显示英文名与制作站。

为原料填入市场价格，并按实际情况设置职业等级、天赋、制作站各模块槽、利润率与每千卡成本，计算器会自动更新产品价格。如果一个物品可由多个配方生产，产品行会显示切换按钮；同一时间只采用当前选中的生产路线计算。

页面设置栏会显示当前内置数据版本。内置快照包含 1,485 条原版配方、1,593 个物品、44 项技能、138 个天赋定义，并支持配方的全部副产品。

原料名称旁的“+”按钮可以快速添加一个能够生产该物品的配方。由此展开的中间产品会自动排列成带连接线的可折叠成本树，层级深度不受限制；若存在多种生产方式，可在产品行切换当前路线。

带品类标签的原料（例如“织物”“破碎岩石”）旁会显示调节按钮。可以选择该品类允许使用的具体物品：单选时直接采用该物品；多选时可让计算器自动采用当前最低成本项，也可指定总计 100% 的固定配比。选中的棉织物、亚麻织物等会缩进显示各自价格，并可继续点击“+”展开其生产配方。品类设置随当前方案保存。

## 副产品

若要把副产品价值计入成本，请在“副产品”区域填写其出售价格。如果需要付费请人处理尾矿，可输入负数；例如处理一单位湿尾矿需支付 1，可填 `-1`。

桶的价值通常不应忽略。可以先查看“产品”区域计算出的桶价格，再把该价格填写到副产品区域。尾矿价格也可能明显影响最终成本，而矿石破碎产生的副产品通常影响较小。

## 自定义配方

设置栏中的“配方编辑器”可以修改任意内置配方、复制为新配方或从空白配方开始创建。修改内容作为当前方案的本地覆盖保存，不会改写内置官方数据；自定义覆盖也会包含在方案导出文件中。需要撤销修改时，在编辑器中选择该配方并点击“恢复官方版本”。

保存配方覆盖时会清空当前已经选择的产品、原料价格和计算链，避免旧配方对象与新数据混用；方案名称、利润率和每千卡成本会保留。建议先完成配方调整，再录入市场价格。

## 计算规则与限制

- 利润率会应用于每一级产品。中间产品再次用于下游生产时，利润率会再次计入，因此长生产链的最终价格会随利润率逐级增加。
- 新版技能劳动曲线、天赋资源/劳动力/产量加成，以及制作站四类模块槽会按照 ECO 14 的动态值规则组合计算。
- 制作时间加成已保留在数据模型中；当前价格公式尚未把电力、燃料或按分钟收取的制作站费用自动折算为成本，可使用配方的“固定成本”补充。
- 未配置具体成员的标签原料仍按标签市场价计算；配置后会按所选具体物品的最低成本或固定配比计算。最低成本模式用于规划可自由替换的材料，若服务器实际消耗有固定比例，应使用固定配比模式。
- 未纳入官方原版数据的服务器自定义内容，可以直接通过网页配方编辑器补充。

## 本地开发

需要 Node.js 与 npm：

```bash
npm install
npm start
```

生产构建：

```bash
npm run build
```

部署到当前 `homepage` 所配置的 GitHub Pages：

```bash
npm run deploy
```

## 更新游戏术语

`src/data/game-zh-cn.json` 保存计算器内置数据所需的中英文术语映射。其译名参考 ECO 官方社区的[简体中文本地化项目](https://localization.play.eco/projects/eco/game/zh_Hans/)。安装 PowerShell 7 后可运行以下命令，根据最新官方术语重新生成映射并检查翻译覆盖率：

```bash
npm run sync:translations
```

脚本只提取本计算器实际使用的短术语；原始英文标识仍保留在状态与导出文件中，因此旧版方案可继续导入。

## 更新原版 ECO 数据

原版数据由 [Eco Gnome 的 MIT 开源服务器导出器](https://github.com/Eco-Gnome/eco-gnome-mod) 从 ECO 服务器运行时生成。仓库内只保留本计算器需要的中英文名称、配方、物品标签成员、技能、天赋、模块和制作站字段。更新游戏版本后运行：

```bash
npm run sync:data
```

生成结果会记录上游提交、数据日期、配方数量与对应游戏版本，方便核对和重复生成。当前快照来自 [`Eco-Gnome/eco-gnome-website`](https://github.com/Eco-Gnome/eco-gnome-website) 的 ECO 14 数据提交。
